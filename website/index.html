Voice, screen sharing, and chat — on a server you run.

VoIPC is an open-source alternative to Discord and TeamSpeak. Messages are encrypted with the Signal Protocol, voice and video with AES-256-GCM, and the relay server keeps nothing: no accounts, no database, no logs.

Download Source

What it does

Three things, done properly: talking, showing your screen, and writing — all encrypted end to end.

Voice

Opus at 48 kHz in 20 ms frames, tuned for speech. RNNoise machine-learning noise suppression runs on-device.

  • Push-to-talk, voice activation, or always-on — with system-wide PTT and mute/deafen hotkeys
  • In-band FEC rebuilds a lost packet from the one that follows it
  • Adaptive jitter buffer grows 40 → 160 ms only when the network needs it
  • Per-user volume, 0–400% mic gain, mic test in settings

Screen sharing

H.265 encoded on your GPU — NVENC, QuickSync, or AMF, with software fallback. Windows builds ship the hardware encoders since 0.4.0.

  • 480p / 720p / 1080p at 30 or 60 fps, 1.5–7.5 Mbps
  • Desktop audio comes along, as 64 kbps Opus
  • Watch fullscreen or in a pop-out window; chat stays visible
  • 1280-byte packets — fits inside WireGuard and OpenVPN tunnels
  • Capture via PipeWire portal on Linux, Windows.Graphics.Capture on Windows

Chat & servers

Channel messages and DMs ride the Signal Protocol — the server relays ciphertext it cannot read. History is optional and stays on your disk, encrypted.

  • Saved servers in the connect dialog; optional auto-connect
  • Password-protected channels, invites, pokes (encrypted too)
  • Local history vault: PBKDF2 + AES-256-GCM, or skip it entirely
  • Persistent rooms via a channels.json on the server
  • System tray and desktop notifications for DMs and pokes

Also in the box

  • Voice quality indicator: live ping and packet-loss in the status bar
  • Audio device hot-recovery when a headset dies mid-call
  • NAT rebind and UDP keepalive — voice survives router timeouts
  • Auto-reconnect keeps trying for 5 minutes across Wi-Fi roams
  • Dead-UDP detection tells you when a firewall eats your voice
  • Android client: voice and screen-share viewing on the go
  • Invite links that open the browser client straight into a channel
  • Admin sessions via a server token: kick and IP-ban, no accounts needed
  • IPv6 dual-stack, TOFU certificate pinning for self-signed certs

Security

Five layers, from the TLS socket to the file on your disk. The server forwards ciphertext it cannot read.

1

Transport — TLS everywhere

  • All TCP control traffic runs TLS 1.2+ via rustls; plaintext connections are refused
  • Self-signed certs are pinned on first connect (TOFU) — a changed fingerprint aborts the handshake
2

Messages — Signal Protocol

  • X3DH session setup, Double Ratchet, per-message keys, forward secrecy
  • Curve25519 identity keys, Ed25519-signed pre-keys, 100 one-time pre-keys auto-replenished
  • Sender keys for channel messages; the official libsignal crate does the crypto
3

Media — AES-256-GCM per packet

  • Random per-channel 256-bit keys, distributed through pairwise Signal sessions
  • Deterministic nonces, domain-separated per stream type — reuse is impossible by construction
  • AAD binds channel and packet type against cross-channel replay; keys rotate before counter exhaustion
4

At rest — your vault, your password

  • Chat history: PBKDF2-HMAC-SHA256 at 600,000 iterations + AES-256-GCM, fresh salt and nonce per file
  • Signal state encrypted separately; every secret wrapped in Zeroizing<T>, wiped from memory on drop
5

Server — blind by design

  • Never sees plaintext messages, never decodes media, never writes to disk
  • Restart equals clean slate: there is nothing to seize, leak, or subpoena

VoIPC has not had an independent security audit. The code is MIT-licensed and small enough to read — audit it yourself.

What lives where

Exactly what is stored, and by whom. No fine print.

Server keeps (RAM only)

  • Usernames & channel membership while connected
  • Channel names and hashed passwords
  • Connection addresses during the session
  • Encrypted media keys and pre-key bundles

Server never sees

  • Message contents
  • Voice, video, or screen content
  • Chat history
  • Your private keys

Your device stores

  • Encrypted chat history (optional)
  • Encrypted Signal Protocol state
  • Audio/video settings, saved servers
  • Max 500 messages per channel, rotated

Nobody stores

  • Analytics or telemetry — there is none
  • Accounts or profiles — they don't exist
  • Server-side message logs
  • Anything after the server restarts

Architecture

Two channels per client: TCP for control, UDP for media. The server is a selective forwarding unit — it routes packets, it doesn't read them.

Download & run

Grab a client from the releases page, then give your group a server: one static binary, a self-signed cert, and port 9987.

Client

Prebuilt packages on the GitHub releases page, or build from source — setup.sh / setup.ps1 installs the dependencies, build.sh / build.ps1 builds. See BUILDING.md for the per-platform details.

Or install nothing: the server hosts a browser client at https://your-server:9987, with the same Signal and AES-256-GCM encryption compiled to WebAssembly.

Releases

Server

# build
git clone https://github.com/luki4fun/voipc
cd voipc && cargo build -p voipc-server --release

# self-signed cert (browsers check the subjectAltName: use your host name / IP)
mkdir -p certs
openssl req -x509 -newkey ec \
  -pkeyopt ec_paramgen_curve:prime256v1 \
  -keyout certs/server.key -out certs/server.crt \
  -days 365 -nodes -subj "/CN=voipc" \
  -addext "subjectAltName=DNS:your-server.example,IP:203.0.113.5"

# run (9987 TCP + UDP, 9988 UDP for browsers)
./target/release/voipc-server

Configure via server.toml or CLI flags; drop a channels.json next to the binary for persistent rooms; set admin_token (or take the one printed in the log) to moderate. The same binary serves the browser client over HTTP/2 and WebTransport (web_port, default 9988; 0 turns it off). A Docker release build (./release.sh) produces a static musl binary, an AppImage, and the web bundle.
